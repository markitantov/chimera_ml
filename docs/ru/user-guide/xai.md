# Шаг объяснимости модели

Шаг XAI измеряет локальную чувствительность предсказания к отключению одной
модальности. Для выбранной оценки h вычисляется

    delta_m = h(f(x_S)) - h(f(x_(S без m))).

Знак показывает направление изменения, а абсолютное значение — чувствительность.
Шаг также сохраняет диагностические значения из ModelOutput.aux, чтобы
сопоставлять внимание, кадровые веса и коэффициенты остаточных поправок с
измеренным изменением.

## Контракт обратного вызова

xai_step оборачивает шаг предсказания. Обёрнутый шаг должен иметь атрибут
on_prediction и вызывать его сразу после каждого прямого прохода модели:

~~~python
@dataclass
class FusionStep:
    on_prediction: Callable[[nn.Module, Batch, ModelOutput], None] | None = None

    def run(self, ctx):
        model = load_model(ctx).eval()
        batch = make_batch(ctx)
        with torch.inference_mode():
            output = model(batch)
            if self.on_prediction is not None:
                self.on_prediction(model, batch, output)
        write_predictions(ctx, output)
        return ctx
~~~

Обратный вызов получает ту же модель, пакет и результат, которые использовались
для обычного предсказания. xai_step временно устанавливает собственный сборщик,
вызывает прежний обратный вызов, если он был, и восстанавливает его даже при
ошибке вложенного шага. Поэтому сборщик вызывается для каждого пакета до
прикладной постобработки.

## Настройка

Вложенный шаг можно передать уже созданным объектом или описанием шага в реестре:

~~~yaml
- name: xai_step
  params:
    step:
      name: fusion_step
      params: {}
    modalities: [audio, video]
    ablation_policy: remove
~~~

Фабрика создаёт вложенный зарегистрированный шаг. Вызываемые объекты Python,
например score_fn и output_mask, нужно передавать из Python-кода; в YAML их
записать нельзя.

## Параметры

- step — шаг предсказания с обратным вызовом.
- modalities — выбранные имена входов; если параметр не задан, используются все
  модальности пакета.
- score_fn — необязательная функция ModelOutput -> тензор. Без неё сравнивается
  output.preds.
- output_mask — имя маски или функция, возвращающая тензор формы оценки либо
  формы оценки без последней компоненты.
- ablation_policy — remove, mask или zero.

Модель и все её вложенные модули должны находиться в режиме оценки. Политика
remove удаляет выбранный вход и его основные маски. Политика mask очищает эти
маски. Политика zero оставляет вход и заменяет его значения нулями.

Модель может реализовать validate_intervention(original, intervened, modality,
policy) -> str | None. Возвращённая строка помечает сравнение как неподдерживаемое.
Опорная модальность также защищена от политик remove и mask.

## Артефакт

В контекст записывается artifacts["xai"]:

~~~python
{
    "ablation_policy": "remove",
    "modalities": ["audio", "video"],
    "samples": [
        {
            "sample_id": "sample-0",
            "baseline": 0.42,
            "modalities": {
                "audio": {
                    "status": "evaluated",
                    "reason": None,
                    "delta": 0.08,
                }
            },
            "aux": {"frame_weights": [[0.6, 0.4]]},
        }
    ],
}
~~~

Статусы: evaluated, already_missing и unsupported. Недопустимые выходные
позиции записываются как null. Вспомогательная функция возвращает среднее
знаковое изменение, среднее абсолютное изменение и порядок модальностей по
абсолютному изменению:

~~~python
summary = summarize_explanations(result.get_artifact("xai"))
~~~

Сравнение качества на размеченной контрольной выборке остаётся задачей
метрики. Артефакт XAI содержит исходные и изменённые предсказания, поэтому
метрика может сравнить качество без привязки шага к конкретной задаче.

## Диагностика моделей

TFS сохраняет внимание и веса пар и групп. RAAV сохраняет кадровые веса, маску
кадров, контекстное внимание и контекстную поправку. TOMAR сохраняет rho_<name>
и delta_<name>. Эти значения описывают внутреннее слияние и не объявляются
причинной важностью.
