# Модели

Структурированный каталог находится на страницах [моделей](../components/models.md) и [сравнения архитектур слияния](../components/fusion.md).

Модель наследует `BaseModel` и реализует `forward(batch: Batch) -> ModelOutput`. `ModelOutput.preds` — основной тензор предсказания, а `ModelOutput.aux` содержит объединённые представления, маски валидности, веса и диагностические данные механизмов внимания.

## Встроенные модели слияния признаков

Четыре встроенные модели получают заранее вычисленные признаки непосредственно из `Batch.inputs`. Они сами создают проекции модальностей и слои предсказания; внешние словари энкодеров и головы предсказания в конструктор не передаются.

| Ключ реестра | Класс | Форма предсказания | Основной механизм |
| --- | --- | --- | --- |
| tfs_fusion_model | TFSFusionModel | [B, output_dim] | Иерархия направленных связей в стиле MASAI и статистическая агрегация |
| tfs_dcmmmoe_fusion_model | TFSDCMMOEFusionModel | [B, output_dim] | Иерархия TFS с адаптивными весами пар |
| raav_fusion_model | RAAVFusionModel | [B, T, output_dim] | Слияние кадров и внимание к латентным векторам контекста |
| tomar_fusion_model | TOMARFusionModel | [B, output_dim] | Остаточные поправки с условием на опорную модальность |

Общие поля конструктора — `input_dims`, `shared_dim` и `output_dim`. Для RAAV обязательны `frame_modalities` и `context_modality`, для TOMAR — `anchor_modality`. Подробности о масках, значениях `aux` и граничных случаях:

- [TFS](tfs-fusion.md)
- [TFS-DCMMOE](tfs-dcmmmoe-fusion.md)
- [RAAV](raav-fusion.md)
- [TOMAR](tomar-fusion.md)

Модальность может отсутствовать в `Batch.inputs` или быть недоступной для образца при ложной маске. Для TFS и TFS-DCMMOE в `Batch.inputs` нужны как минимум два тензора модальностей, чтобы сформировать пару; если все их временные позиции замаскированы, `fused` становится нулевым, но предсказание всё равно возвращается. RAAV требует одинаковую длину последовательности у присутствующих кадровых модальностей, но временная шкала контекста может отличаться. TOMAR требует опорную модальность (`anchor`) для каждого образца.

Модели можно создать через классы Python или через реестр `MODELS` из YAML. В [справочнике API](../api/models.md) приведены публичные классы и фабрики.
