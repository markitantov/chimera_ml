# Конфигурация конвейера

YAML инференса отделён от YAML обучения и оценки. `InferenceConfig` читает `pipeline`, необязательный `runtime` и список `steps`.

| Поле | Тип и значение по умолчанию | Назначение |
| --- | --- | --- |
| `pipeline.name` | строка, `inference_pipeline` | Имя конвейера. |
| `pipeline.parallel` | bool, `false` | Включить планирование DAG. Значение не типа bool вызывает `TypeError`. |
| `runtime.device` | строка, `auto` | Запрошенное устройство; CLI разрешает его в `cpu` или `cuda`. |
| `steps` | список, `[]` | Шаги конвейера. Для каждого отображения требуется `name`. |
| `steps[].id` | строка, по умолчанию `name` | Уникальный идентификатор узла; нужен, когда имя шага повторяется. |
| `steps[].after` | строка или список строк, `[]` | Зависимости в параллельном режиме. |
| `steps[].params` | отображение, `{}` | Именованные аргументы зарегистрированной фабрики. |

```yaml
pipeline:
  name: demo
  parallel: false
runtime:
  device: auto
steps:
  - name: my_prediction_step
    params: {}
  - name: write_json_predictions_step
    params:
      output_path: outputs/predictions.json
```

Минимальная форма конфигурации структурно корректна, но сама по себе не исполняется: средство печати всё равно требует, чтобы предыдущий шаг опубликовал артефакт `predictions`.

## Переопределения CLI и вывод

Флаги CLI не переписывают произвольные поля YAML. `--device` переопределяет устройство среды выполнения только для текущего запуска. В последовательном режиме `--output` создаёт средство записи, если его нет, или переопределяет `write_json_predictions_step.params.output_path`; в параллельном режиме средство записи нужно объявить явно и задать зависимости `after`.

`--work-dir` не является полем YAML. Он передаётся в `InferenceContext.work_dir` для текущего запуска. Шаги интерпретируют относительные пути к кэшу и промежуточным данным относительно этого каталога, а встроенный кэш контрольных точек также разрешается относительно него.

## Имена шагов и регистрация

Отображение шага разрешается через `INFERENCE_STEPS`. Имя должно быть зарегистрировано в процессе CLI. `id` меняет только идентификатор узла графа, а не ключ реестра; `after` может быть одной строкой или списком строк.

Каждый `name` должен быть ключом `INFERENCE_STEPS`. Необязательный `params` передаётся зарегистрированной функции построения; не указывайте параметры, которых нет у компонента.

В последовательном режиме построитель добавляет зависимость каждого шага от предыдущего и игнорирует `after` при планировании. В параллельном режиме `after` задаёт DAG; повторяющиеся идентификаторы, зависимость от самого себя, неизвестные зависимости и циклы отклоняются до запуска. Узлы без `after` являются независимыми корнями и могут выполняться одновременно.
