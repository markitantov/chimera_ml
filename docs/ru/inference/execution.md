# Последовательные и параллельные конвейеры

## Последовательный режим

При `parallel: false` или отсутствии этого поля шаги выполняются в порядке списка. Каждый следующий шаг получает артефакты предыдущего. Это естественная цепочка «подготовка → предсказание → запись»:

```yaml
pipeline: {name: sequential, parallel: false}
steps:
  - name: prepare_step
  - name: prediction_step
  - name: write_json_predictions_step
```

В этом примере `prepare_step` и `prediction_step` — ключи плагина; проверьте их через реестр. Встроенными являются только реальные ключи из [каталога](built-in-steps.md).

## Параллельный DAG

При `parallel: true` конвейер строит граф. Узлы без незавершённых зависимостей `after` могут выполняться одновременно в разных потоках. Это параллелизм шагов, а не автоматическое распараллеливание батчей модели.

```yaml
pipeline:
  name: dag
  parallel: true
steps:
  - id: prepare
    name: prepare_step
  - id: predict
    name: prediction_step
    after: prepare
  - id: diagnostics
    name: diagnostics_step
    after: prepare
  - id: write
    name: write_json_predictions_step
    after: predict
```

Каждый узел получает копию артефактов предыдущих узлов. При объединении учитываются только ключи, записанные через `set_artifact`. Перезапись разрешена последующему узлу, зависящему от предыдущего владельца; независимая конфликтующая запись даёт `ValueError`. Повторяющиеся идентификаторы, неизвестные зависимости, зависимость узла от самого себя и циклы отклоняются до выполнения.

Для XAI средство экспорта должно зависеть от узла `xai`. В последовательном режиме поставьте его после `xai_step`; в DAG задайте `after: [xai]`. Аналогично средство записи результата должно зависеть от шага, создавшего `predictions`.
