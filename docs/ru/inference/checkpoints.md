# Чекпоинты и артефакты

Модельная контрольная точка — это файл с состоянием модели, а артефакт инференса — любое именованное значение, которым обмениваются шаги. Шаг ядра разрешает файлы контрольных точек; шаг предсказания плагина отвечает за построение модели, загрузку словаря состояний, перенос модели на `ctx.device` и проверку совместимости архитектуры.

## Разрешение локальных и удалённых контрольных точек

`resolve_checkpoints_step` разрешает локальные пути и URL HTTP(S), но не строит модель и не загружает веса. Для локального файла результат — абсолютный путь. Для URL используется кэш в `work_dir/cache_dir`; существующий файл переиспользуется при `force_download: false`. Скачивание идёт в `.part`, тайм-аут HTTP-запроса — 30 секунд.

```yaml
- name: resolve_checkpoints_step
  params:
    checkpoints:
      encoder: /models/encoder.pt
      fusion: https://example.org/fusion.pt
    cache_dir: checkpoints
    force_download: false
```

Следующий шаг предсказания читает `ctx.get_artifact("checkpoints")`, выбирает логический ключ, строит совместимую модель, загружает словарь состояний и переводит модель в `eval()`. Формат весов и совместимость модели определяются шагом плагина.

`InferenceContext` содержит `input_path`, `work_dir`, разрешённое устройство `device`, исходный `config` и отображение артефактов. `set_artifact(name, value)` публикует значение и отмечает его как записанное текущим шагом; `get_artifact(name, default)` читает его. `ctx.predictions` — сокращение для артефакта `predictions`.

## Передача артефактов через контекст

Следующие операции показывают типичный обмен значениями между шагами:

```python
checkpoint = ctx.get_artifact("checkpoints", {}).get("fusion")
ctx.set_artifact("features", features)
ctx.set_artifact("predictions", predictions)
output_path = ctx.get_artifact("output_path")
```

Используйте `get_artifact` со значением по умолчанию для необязательных данных, а `set_artifact` — для каждого значения, которое должны получить последующие шаги. Конвейер отслеживает записанные ключи и проверяет владение ими при объединении DAG. `ctx.predictions` — свойство-алиас для `get_artifact("predictions")`. Встроенное средство записи публикует `output_path` после записи; при использовании Python API промежуточные артефакты остаются в итоговом контексте, даже если средство записи JSON их не сериализует.

## Совместимость при загрузке

Одно лишь разрешение контрольной точки не проверяет модель. Шаг плагина должен загрузить ожидаемый формат словаря состояний и выдать понятную ошибку, если не совпадают архитектура модели, имена модальностей или размерности тензоров. Сохраняйте ключи контрольных точек между шагом разрешения и шагом предсказания; например, используйте `checkpoint_key: fusion`, если шаг разрешения публикует `checkpoints.fusion`.

В параллельном режиме конвейер объединяет только ключи, явно записанные через `set_artifact`, и проверяет их владельцев. Поэтому стандартное средство записи JSON экспортирует только `input` и `predictions`, а не весь контекст и не `xai`; для XAI нужен отдельный шаг вывода, описанный в [XAI](../user-guide/xai.md).
